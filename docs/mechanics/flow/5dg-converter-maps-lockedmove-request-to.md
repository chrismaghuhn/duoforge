5dg. **The converter maps a lockedmove request to the locked move's slot (issue 516; branch claude/516-converter-lock; found by the differential fuzzing of issue 396).** Pin: a member with the `lockedmove` volatile (Outrage, Thrash, Petal Dance) gets a request with a single move row, the locked move (`sim/pokemon.ts:1083-1095`), and `chooseMove` with a locked move ignores the typed index, target and mega (`sim/side.ts:675-690`); so the trace's "move 1" names that row, not the member's first move. `tools/reference/trace_to_c.py` took the single row as bit 0 of the enabled mask and the choice as slot 0, so an Outrage in a slot other than the first was offered and chosen in the wrong slot. Now `locked_move_slot` finds the member's last `|move|` line, maps the move into its set (a move not in the set or no move line is refused, `locked-move-slot`), the enabled mask is that slot's bit, and `convert_choice` takes the slot from `locked_slots` (a locked member without a given slot is refused, `not-given`). A single row for a member with more than one move and no known lock is refused (`request-single-row`), never read as slot 0. The callers of `convert_choice` (`tools/reference/diff_random.py` and the test drivers of `diff_random`, `python/tests/replay` and `python/tests/live`) pass the locked slots. Other locks: Choice lock is soft at the pin (all rows, the others disabled) and was already right; Thrash, Petal Dance, Uproar, Rollout and Bide are not supported by the engine, so only Outrage reaches this path. No C code changes; every committed payload is byte-equal (`trace_to_c.py --check`). **Evidence.** `tools/reference/tests/test_trace_to_c.py`: a library test on `g56_outrage_full` with Outrage moved to slot 1 (the locked steps offer and choose slot 1) and a refusal test (the move not in the set, an unknown lock, no slot given); both are red on main. Three mutants of the new code are each killed by these tests. The fuzz batches 1 to 3 rerun with the converter: DIVERGENCE 51 to 24 (the rest are issues 517 to 522 and recharge cases of 517), UNSUPPORTED 11 to 13, ORACLE_GAP 8 unchanged.
