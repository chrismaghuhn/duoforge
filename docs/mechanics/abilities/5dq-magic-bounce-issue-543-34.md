5dq. **Magic Bounce of issue 543: 34 cases, two causes (branch claude/project-thread-fxsdy2; found by the differential fuzzing of issue 396).** One commit each, both in `dfi_bounce` (`src/combat/turn.c`). (a) **A bounced Leech Seed on a Grass source** (fz_254_28, 31 cases): the bounced run checks Leech Seed's onTryImmunity (`data/moves.ts:10202-10231`) in hitStepTryImmunity, before the accuracy step, as the move body does; the engine rolled the accuracy first and so drew where Showdown does not (E_INVARIANT at an empty tape). (b) **A bounced priority move against Queenly Majesty** (fz_125_101, 2 cases): the bounced move keeps the original move's priority (`sim/battle-actions.ts:409-412`; Baby-Doll Eyes has its own), and a Queenly Majesty or Armor Tail holder on the source's side stops it in TryMove (`data/abilities.ts:3716-3734`): the bounced line gets [still], then cant|holder|ability|move|[of] the bouncer, and the bounced move is false. The engine refused the Armor Tail case (E_UNSUPPORTED) and missed Queenly Majesty; both now run the same handler as the move body's TryMove. `duoforge.abilities.magic_bounce` pinned the Armor Tail refusal; it now checks the [still] line and the cant line instead. A Psychic Terrain under such a move is still refused. **Evidence.** Two recordings (`tests/reference/specs/fz543_*.json`, whole battles; seeds and choices of the campaign, traces from the pinned Showdown b2cb775). All 34 cases pass the runner (the two of (b) are fz_125_101 and fz_417_45; one case already passed before these fixes). Mutants, each fix reverted alone: each is killed by its own recording and not by the other. Every other reference battle is unchanged; the pool set grows by these two. No Armor Tail bounce is recorded; it takes the same branch as Queenly Majesty, as in the move body.
