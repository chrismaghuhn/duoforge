# 5f. G17, the recharge moves

- Area: moves
- Step: G17
- Tests: duoforge.reference.conformance_pool_data, duoforge.state.pool_g17

5f. **G17, the recharge moves** (the fourth mechanic on the tail: `must_recharge` of section 7, rev 2 as it is; M11 lists must recharge as #7 of the replay frequencies, Hyper Beam blocks 20 of the 227 survey teams). The seven recharge moves of the pool (Blast Burn, Frenzy Plant, Giga Impact, Hydro Cannon, Hyper Beam, Meteor Assault, Rock Wrecker) become data: a new bit of the second flags byte, `DFI_MOVE_FLAG2_RECHARGE` (8), which the generator reads from exactly the pinned text (`flags: {recharge: 1, ...}` with `self: { volatileStatus: 'mustrecharge', }`; one without the other is a refusal) and which takes the seven rows out of the UNMODELED rows (313 to 306). The POOL fingerprints change (`fc1d4a74...` for the tables, `9ef5db6a...` for POOL and `b6678904...` for POOL_DEV); CLOSURE and TEAM_C are byte for byte unchanged.
   - **The pin.** `data/conditions.ts:364-378`: `mustrecharge` has `duration: 2`, `onBeforeMovePriority: 11`, an `onBeforeMove` that shows `cant|X|recharge`, removes the volatile (and `truant`) and returns null, an `onStart` that shows `-mustrecharge|X` (`sim/SIM-PROTOCOL.md:603`) and `onLockMove: 'recharge'`. The ten moves with the flag (`data/moves.ts:1414-1429, 4936, 6242-6257, 6573-6588, 9055-9070, 9113-9128, 11723-11738, 13953, 15180, 15307-15322`; Meteor Assault has 170 power in the Champions mod, `data/mods/champions/moves.ts:635-639`) carry the volatile as a `self` effect, which `selfDrops` applies (`sim/battle-actions.ts:1096, 1317-1335`) for every target that was not ruled out: a miss, a Protect or an immunity make the target `false` and give no recharge; a knocked-out target is still a hit. A second `addVolatile` changes nothing, so one `-mustrecharge` line per move. `sim/pokemon.ts:964-972, 1084-1090, 1137`: the request of the next turn is the one move `Recharge`, the Pokemon trapped, no Mega; `sim/side.ts:575-583, 675-689` accept "move 1" and queue `{choice: 'move', moveid: 'recharge'}`. `runMove` (`sim/battle-actions.ts:210-264`) gets a random target for it (the name is no move: `getTarget` falls to `getRandomTarget`, one RANDOM_TARGET draw with two foes standing, kept as a tape entry like every other draw of that call; it decides nothing), asks `OverrideAction` (Encore, :227-235: an Encored Pokemon has the action turned into the Encored move and a second random target, a second draw), and `BeforeMove` ends it before PP are deducted and before `moveUsed`: no PP, no change of `lastMove`. The volatile ends with the occupant (`clearVolatile`, as for Soak).
   - **State and rules.** `must_recharge` (0 or 1) of the position is the only state; the turn code sets it after the hit loop's self step (`-mustrecharge` is the `VOLATILE_START` event with the detail `DUOFORGE_VOLATILE_MUST_RECHARGE` = 3), `dfi_before_move` takes it first (priority 11, before sleep and freeze, flinch, Throat Chop, confusion and paralysis) for whatever move the action holds, shows `cant|X|recharge` (the `CANT` event with the cause `DUOFORGE_CAUSE_RECHARGE` = 18) and clears it. The recharge action is counted as a move action (Fake Out's rule counts it too: `activeMoveActions`). Encore on a Pokemon that must recharge replaces the queued recharge action by the Encored move, which then recharges all the same (the volatile is still there); an Encored Pokemon on its recharge turn has the override draw. Sucker Punch fails against a Pokemon with the volatile (`data/moves.ts:18405-18411`). **The residual sort.** `mustrecharge` has a duration and no callback, so it is an `end` handler of the residual's speed sort, as the stall counter is: the engine's list has one more duration entry per position that must recharge (`DFI_RES_PER_POSITION` is 11), because the swaps of the sort move tied entries and so decide the order of two Grassy Terrain heals at equal Speed (found by the first differential run, case `fz_9171_50`: a Hydro Cannon user and its tied ally).
   - **Request and choice (owner decision).** The slot of a Pokemon that must recharge is offered exactly one candidate: MOVE with `move_slot` = `DUOFORGE_MOVE_SLOT_RECHARGE` (5, next to Struggle's 4), no target, no Mega; no switch, no other move. `DUOFORGE_SLOT_PASS` keeps its meaning (an empty or fainted slot). The queue record of the action has the same move slot (the state checker allows it), and a decoded state with a queued move slot 5 is valid from now on (the tests that used 5 as the first invalid slot use 6).
   - **View.** Decision 0018: the `MUST_RECHARGE` bit of `position_ext.volatiles`, supported bit 15; public to both viewers (set by `-mustrecharge`, cleared by the `cant` line and by the occupant leaving). No new field.
   - **Converter and harness.** `-mustrecharge` and `cant|X|recharge` map to the two events above; the choice of a recharge turn (the state's `volatiles` has `mustrecharge`, Showdown's "move 1") is MOVE with slot 5; the reference's `enabled` row of such a request is the bit 0x20 (the recharge slot). The harness is unchanged (the state dump already lists `volatiles`), so no committed trace changes.
   - **Meteor Assault stays unmarked.** Its only learner, Sirfetch'd, has no supported ability (Steadfast and Scrappy), so no setup can use it; its row carries the bit and the Champions power (170) and the test says so. The survey team that has it is blocked by the ability first.
   - **Evidence.** Eleven recorded battles under the POOL kind (`g17_hyper_beam`: a hit, the recharge turn, the turn after; `_protect`: Protect stops it; `_immune`: a Ghost; `_miss`; `_ko`: a knocked-out target still gives it; `_encore`: Encore on a Pokemon that must recharge, and the recharge turn of an Encored Hyper Beam; `_sucker`: Sucker Punch fails against the recharging target and works as a control a turn later; `_flinch`: Fake Out on the recharge turn shows only `cant|recharge`; `_scarf`: a Choice Scarf holder is locked into Hyper Beam after its recharge; `g17_recharge_moves`: Blast Burn, Frenzy Plant, Hydro Cannon and Rock Wrecker recharge together; `g17_giga_impact`: Giga Impact and Hyper Beam together); `duoforge.reference.conformance_pool_data` compares every event, HP, request and the tape (consumed exactly), `duoforge.state.pool_g17` reads the tail, the candidates of every slot and both viewers' extension after every step against rows that `test_trace_to_c.py` derives from the protocol lines, and refuses another move, a switch or a pass for the recharging slot. `tools/datagen/pool_families.js` checks the pinned facts (the ten moves, the condition, Sucker Punch's `onTry`). The differential loop under the machine lock (teams of Hyper Beam, Giga Impact, Hydro Cannon, Blast Burn, Sucker Punch, Fake Out and Encore users against the closure teams and each other): the first run (100 battles, seed 9171) found one divergence, fixed here and promoted into the corpus (`fz_9171_50_prefix`); the fixed engine then ran 100 battles (seed 9171) and 200 (seed 9172, with Encore teams): all PASS, with 1045 `-mustrecharge` lines and 894 `cant|X|recharge` lines in 268 battles, and the engine offered what Showdown accepts in all 1430 sampled requests. Mutation checks (no volatile, set without a hit, a knocked-out target not a hit, a recharge flag ignored for one move, no start event, no cant event, the volatile not cleared, the recharge check after the flinch, no recharge candidate in the request, no view bit, no base random-target draw, no Encore override draw, a recharge action that resets the move counter) each fail a test; one survivor, Sucker Punch's own `mustrecharge` test next to the queue-record test, is unreachable (an Encore that replaces the recharge action acts after Sucker Punch, whose priority is +1) and is kept because the pin has it.
