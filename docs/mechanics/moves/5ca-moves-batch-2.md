5ca. **G64, moves batch 2** (lane A builder H4: Beat Up, Bug Bite, Sheer Cold and Poltergeist marked; Dragon Darts dropped). No new public value (no header constant, event kind, cause, view bit or tail byte), no new state: the lead's answer of 2026-10-09 on `-ohko` (a narrow converter drop, no event) and on `-immune [ohko]` (IMMUNE with cause NONE) is what the rows use. Handler ids 82 to 85 (`BEAT_UP`, `BUG_BITE`, `POLTERGEIST`, `SHEER_COLD`), `UNMODELED` 86; the pool table hash is `4e7c7e6d4be962329bd0e89c29c0d57689fca73ef2d0f2fba06d6e92b43ac5e5`, the POOL fingerprints KP `9ed6582e13ea56edafa0b205ab4ed548d3cf190472652ad29a402a56b638d2ca` and KPD `7740436a168ab341c4e7042a1813f1e7681579302afe1aa166aac86207edf045`.
   - **Beat Up** (`data/moves.ts:1150-1179`, no Champions override): `onModifyMove` keeps the side's Pokemon that are the user or are not fainted and have no status, in `side.pokemon` order, and sets `multihit` to their number; `basePowerCallback` gives each hit `5 + floor(base Attack of its set species / 10)`. The hit count is the number of brought members in `party_order` (G46, which the switches keep equal to `side.pokemon`) that pass the test; the base Attack is `dfi_pool_formes[species_id]` (the set's forme, not the Mega forme). The hit list is built once when the hit loop starts (`dfi_beat_up_hits`, `dfi_run.beat_up_bp`), and the damage reads it by `hit_index` (`dfi_get_damage`). The accuracy is checked once (no multiaccuracy), the loop ends when the target falls or the user does (Rocky Helmet on each contact hit), and `-hitcount` is the converter's usual check.
   - **Bug Bite** (`data/moves.ts:1911-1931`, `onHit`; no Champions override): with the user alive and a berry (`item.isBerry`: Sitrus, Lum and the resist berries, Chilan and Chople included) on the target, `takeItem(source)`: a live Sticky Hold shows `-activate|X|ability: Sticky Hold` and keeps the berry (as Knock Off does); otherwise `-enditem|X|Berry|[from] stealeat|[move] Bug Bite|[of] user` (ITEM_END, cause ITEM_TAKEN, the move in id, the user in other, the EATEN flag), then the berry's `Eat` for the user with no TryEatItem (no Unnerve test): Sitrus heals the user by a quarter (`data/items.ts:5744-5767`; the heal is not shown at full HP and a Heal Block refuses it), Lum cures the user's status and confusion (`data/items.ts:3537-3560`; `dfi_lum_cure`, split out of `dfi_lum_berry` with no change of behaviour), and a resist berry's `onEat` is empty. The call stands after DamagingHit and before Knock Off's after-hit block (`dfi_bug_bite`).
   - **Sheer Cold** (`data/moves.ts:16198-16213`, `ohko: 'Ice'`, owned by its handler in `G2_OWNED_FIELDS`). Its turn-code path: Sturdy's `onTryHit` (`data/abilities.ts:4675-4680`, Sturdy is marked since G39) shows `-immune|X|[from] ability: Sturdy` in the TryHit ability chain, before any draw; in the accuracy loop an Ice-type target is `-immune|X|[ohko]` (IMMUNE, cause NONE, no miss line, no draw), otherwise the accuracy is 30 for an Ice user and 20 for any other (`dfi_ohko_accuracy`: No Guard and Glaive Rush's onAccuracy answer first with no draw; the stages, Compound Eyes, Wide Lens and the powder items are not applied, as the pin's ohko branch skips ModifyAccuracy; `sim/battle-actions.ts:696-713`). The damage is `target.maxhp` before the crit and the formula (`sim/battle-actions.ts:1606`, the Super Fang pattern), so a full-HP Focus Sash leaves 1 HP as the generic path does. The pin prints `-ohko` after the faint of the target (`:976` faintMessages, then `:999`), which the converter checks and drops (`ohko-line`, the lead's rule: no event, only after the faint of the target of a Sheer Cold hit).
   - **Reachability, stated rather than recorded.** Every learner of Sheer Cold in the Champions learnsets is an Ice type (Glalie, Abomasnow, Vanilluxe, Beartic, Mr. Rime), so the accuracy 20 branch (a non-Ice user) cannot occur in POOL and is implemented but not reached. The level term is 0: every Champions Pokemon is level 50 (the spec's `Level: 50`), so no battle can show it either. Vanilluxe's Ice Body is unmarked, so the Ice-immunity battle uses Abomasnow (Snow Warning, marked).
   - **Poltergeist** (`data/moves.ts:13595-13608`): `onTry` (`!!target.item`) fails with `-fail` and `[still]` before any draw when the target holds no item (`dfi_item_code`: the item now, the tail's `item_now` included). Its `onTryHit` runs in `spreadMoveHit`'s singleEvent (`sim/battle-actions.ts:1044`), after the accuracy and the type immunity, so a miss, an immunity (a Normal type against a Ghost move: no line) and a Protect show no reveal. The line `-activate|X|move: Poltergeist|Item` is an ACTIVATE of the move (cause MOVE, id2 the move); the converter checks that the item name is an item of the tables. The item is already public (the member view's `item` is the open sheet item, and `item_now` is public since G29), so nothing new is revealed.
   - **Dragon Darts: dropped** (not built). `smartTarget` is not a field of the pool columns and its behaviour is a three-way state machine across the hit steps (`sim/pokemon.ts:757-768` `getSmartTargets` chooses the partner; `sim/battle-actions.ts:607, 633, 661, 739, 896-950` clear the flag at Protect, invulnerability, accuracy and a failing target, and the hit loop then retargets per hit with `-anim` and `retargetLastMove`). The engine has no two-target single-move path (`dfi_run_move`: `E_UNSUPPORTED` for a multi-hit spread), so the row needs a new target model, not a mark. Left for a later step with its own proposal.
