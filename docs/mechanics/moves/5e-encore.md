# 5e. G9, Encore

- Area: moves
- Step: G9
- Tests: duoforge.reference.conformance_pool_data, duoforge.state.pool_g9

5e. **G9, Encore** (the third mechanic on the tail: `last_move`, `encore_slot` and `encore_turns` of section 7, rev 1 as it is). Encore keeps its handler id (`DFI_SPECIAL_ENCORE`; no table change, so no fingerprint change) and the turn code implements it; it is marked.
   - **The pin.** `data/moves.ts:4724-4783`: a Normal status move, accuracy 100, flags protect, reflectable, mirror, bypasssub, metronome, failencore; condition `encore` with `duration: 3`, `onOverrideAction`, `onResidualOrder: 16` and `onDisableMove` (every slot but the stored move is disabled). The Champions mod replaces `onStart` (`data/mods/champions/moves.ts:309-345`): it fails (`-fail|user|[still]`: the move did nothing) without a `lastMove`, for a `failencore` move (Struggle and Encore are the only two with the flag) and for a stored move with 0 PP; otherwise `-start|target|Encore`, and when the target still has a move queued (`queue.willMove`) that is for another move and the target holds no Mental Herb, `queue.changeAction` replaces the action by the encored move. `addVolatile` refuses a target that has the volatile (there is no `onRestart`), which gives the same `-fail`. The duration is 3, or 4 when the target has no move queued (it has moved this turn, or is about to switch: the `+1` that the pin adds at `onStart`), counted down once per residual at order 16 (callback, so two holders at one Speed draw SPEED_TIE, which the sort entry `DFI_RES_ENCORE` takes part in); `-end|target|Encore` when the counter reaches 0 or the stored move has 0 PP. `Pokemon.lastMove` is the last move that the Pokemon itself used (Struggle included, stored as 5): the engine writes it where the move is used (`r->move_used`), under the POOL kinds only (the tail is all zero otherwise, `TAIL_KIND`). A switch-out, a faint or a replacement clears the tail position (`dfi_tail_clear_occupant`; a Mega Evolution does not, the volatile stays), so the Encore and the last move end silently with the occupant.
   - **The replacement and its draws.** `BattleQueue.changeAction` cancels the target's actions and `insertChoice` (`sim/battle-queue.ts:301-305`, `369-403`) puts the new action, which has no target, back: `resolveAction` first picks the target (`Battle.getRandomTarget`, `sim/battle.ts:2490-2522`: self, side and field moves target the user; an ally move the standing ally with one draw; otherwise `side.randomFoe()`, one RANDOM_TARGET draw `random(0, alive foes)`), then the action goes before the first queued action that it beats (`comparePriority`: order, priority with the user's ModifyPriority handlers, the user's action speed after `updateSpeed`); among queued actions that it ties it lands at `random(first, last + 1)`, a new draw site INSERT_TIE (`DFI_SITE_INSERT_TIE` = 14, drawn only when the range has more than one index). Every later sort in the turn recomputes every priority from the move and shuffles ties again (`sim/battle.ts:2921-2925`), so the place only matters for the tape: the engine takes the value from the reference and consumes it. The queue record of the replacement keeps the activation and the user, takes the new slot and the target, and has no reserve (the bench member that was chosen for a pivot move: the new action is built from the move alone).
   - **Request.** `dfi_slot_candidates` skips every move slot but the encored one while `encore_slot != 0` (a locked slot with 0 PP, or Fake Out disabled by the Champions rule after turn 1, leaves nothing and the slot gets Struggle: `g09_encore_struggle`); Choice locks and the other disables are applied as before, on the one slot that is left.
   - **Harness and converter.** `ps_trace.js` tested `insertChoice` before `getRandomTarget`, so Encore's random-target draw was recorded as INSERT_TIE/queue (team-gaps finding F5 a). The label is now RANDOM_TARGET (`resolve:insert`, or `action-speed` when `getActionSpeed` asked for it) when `getRandomTarget` is on the stack, INSERT_TIE only for the insertion's own draw; no committed trace holds a `changeAction`, so every older trace is byte for byte the same and the harness version stays 14. The converter's rules: the RANDOM_TARGET `resolve:insert` draw is kept (it decides the target, unlike the draws that only feed ModifyPriority); an INSERT_TIE is kept as a tape entry when its range holds moves and only move or residual actions; `-start|X|Encore` and `-end|X|Encore` become `VOLATILE_START` and `VOLATILE_END` (below); the `encore` volatile is ignored in the volatile lists; DisableMove tie groups accept the `H:encore:` entries. `test_trace_to_c.py` derives the expected slot of the lock per position and step from the protocol lines, and two tests pin the converter rules (a control without the rule is red).
   - **Events.** The two events of G8 are used with a new public detail value: `DUOFORGE_VOLATILE_ENCORE` = 2 (`VOLATILE_START` and `VOLATILE_END`, detail 1 being Heal Block; owner approval of the value asked with the PR). Position of the target; both viewers see the line.
   - **View.** Decision 0018 section 6.1 and the extension: `position_ext.encore_slot` (slot + 1), supported bit 7 (`DUOFORGE_VIEWEXT_FEATURE_ENCORE`), set by this step; public to both viewers. No new field. The tracker's rule is the table row of section 6.1: `-start|X|Encore` sets it (to the slot of the last `|move|` of the occupant), `-end|X|Encore` and OUT clear it.
   - **Evidence.** Eight recorded battles under the POOL kind (`g09_encore_lock`: Encore before the target moves, the queued move is replaced with a random target, the requests offer one slot, the lock ends after three turns; `_late`: duration 4 for a target that has moved; `_fail`: no last move, the same move queued again (no replacement), Encore on an Encored target; `_encore`: Encore on a target whose last move is Encore (the failencore flag: `-fail`), and an Encore on a target that has moved (duration 4); `_switch`: the lock ends silently with the occupant; `_struggle`: Encore on Fake Out; `_tie_a`, `_tie_b`: a replaced action that ties an equal-Speed action, the two seeds being the two insertion outcomes, 0 and 1); `duoforge.reference.conformance_pool_data` compares every event, HP and request and consumes the tape exactly, `duoforge.state.pool_g9` reads the tail and both viewers' extension after every step against rows that `test_trace_to_c.py` derives from the protocol lines, plus the request domain under the lock, Struggle, the 0-PP early end and an Encore on a target whose last move is Struggle (state pokes, the second on the engine's own predicate) and the predicates against the pin's name list (which `tools/datagen/pool_families.js checkEncore` checks against the pin's text: duration 3, order 16, the flags and the callbacks). A campaign under the machine lock (120 battles, seed 9101, teams with four Encore users against the closure teams: 155 Encore starts in 73 battles, 89 `-end` lines) was 120 PASS. Mutation checks (no request lock, no replacement, a wrong duration, no late bonus, no residual entry, no INSERT_TIE draw, no RANDOM_TARGET draw, no view slot, the failencore list, the 0-PP end, the end event) each fail a test.
