5de. **K3, Speed Swap (issue #473; branch content/473-speed-swap; merged with main 29418887, which holds #476 and #474).** Pin: `data/moves.ts:17430-17449` speedswap: Status, BP 0, accuracy true, PP 10, priority 0, flags protect, mirror, bypasssub, allyanim, metronome, target normal, type Psychic; `onHit` exchanges `target.storedStats.spe` and `source.storedStats.spe` and prints `-activate|source|move: Speed Swap|[of] target`. Champions has no override (`data/mods/champions/moves.ts` names no speedswap). `mirror` is Mirror Move's flag, not `reflectable`: the move is not reflected. The owner's request shows the unswapped Speed of the current forme (`sim/pokemon.ts:1159-1165`, `baseStoredStats`). Stored stats are rebuilt by `setSpecies` (clearVolatile, `sim/pokemon.ts:1559`; formeChange, Mega and Stance Change), and the residual's `updateSpeed` (`sim/battle.ts:2810-2820`) takes the order from them.

Engine: the exchange is `src/combat/moves/stat_swap.h`, the stored Speed of both members (`dfi_member.stats[SPE]`), not the staged one. The presence bit is `DFI_SINGLE_TURN_SPEED_SWAP` (value 4, bit 2 of the tail `single_turn` byte, `src/state/battle_internal.h:282`), set on both positions. It persists across turns: the residual never clears it, and it must never be cleared together with the byte. Clears: a switch-out or a faint resets the position and rebuilds the occupant's stored Speed (`src/state/identity.c`, `dfi_tail_clear_occupant`); a Mega Evolution (`dfi_run_mega`) and a forme change of Stance Change (`dfi_stance_change`, `src/combat/turn.c`) clear the bit of that position only; the partner keeps its swapped Speed. The invariant (`src/state/invariants.c`, around line 215) accepts the swapped Speed on a live swap, including the G66 Blade branch (Speed exception).

Public values (`include/duoforge/`): cause `DUOFORGE_PUBLIC_CAUSE_SPEED_SWAP` 128 (`duoforge_view.h`), set by the battle path (`duoforge_battle_public_causes`, `src/state/view.c`) and the public record check; the observation call `duoforge_observation_causes` never reports 128 (the documented limit, as for SUBSTITUTE). Position extension `DUOFORGE_POSITION_EXT_SPEED_SWAPPED` bit 23 (0x00800000), presence only, reported under view feature `DUOFORGE_VIEWEXT_FEATURE_SPEED_SWAPPED` 46 (RESERVE_OWN entry, `include/duoforge/duoforge.h`). Volatile `DUOFORGE_VOLATILE_SPEED_SWAP` 16 (VOLATILE_START, position source, other target; no END). The numbers 16 and 46 are the free ones (15 and 44 are kept for Focus Energy and Last Resort).

View and tracker: the owner view shows the unswapped Speed (pin above); the foe's view shows the presence bit only, never a value. `python/duoforge_live/tracker.py` folds the start line into the presence bit and clears it on a forme change, Mega, switch and faint. The live record is refused with cause 128 while a bit stands and accepted again after the last swapped occupant has left.

Recordings (POOL kind, eleven, `tests/reference/battles/reg-mc/pool/k3_*`): `k3_speed_swap_basic` (exchange with the foe; the next turn's order follows the swapped Speeds), `k3_speed_swap_ally` (exchange inside the own side), `k3_speed_swap_same_turn` (the queue re-sorts after the swap: the swapped foe moves before a later action of the same turn), `k3_speed_swap_protect` (blocked by Protect, nothing swaps), `k3_speed_swap_switch` (the swapped foe switches out, its bit ends; the other side keeps its bit until it leaves), `k3_speed_swap_faint` (a faint ends the swap of the fainted occupant), `k3_speed_swap_mega` (the Mega clears its own bit only), `k3_aegislash_blade_swap` (the Blade's G66 Speed exception), `k3_aegislash_shield_reset` (Stance Change clears the bit and the Speed is the forme's again), `k3_speed_swap_mega_end` (Alakazam's Mega clears its own bit, Milotic's bit ends when it switches out: refused until then, accepted after) and `k3_aegislash_swap_end` (Stance Change clears Aegislash's bit, Alakazam switches out, King's Shield returns Aegislash to the Shield forme: accepted after). The per-battle pins are in each file. Pins that changed after the first seeding: `k3_speed_swap_protect` only (live outcomes equal 4 to 6, move-result-not-determined 2 to none), with the cause below.

Mutants (twelve, one at a time on the merged tree, each reverted to a clean tree; killed by every listed test): M1 no swap of the user side (killed by duoforge.moves.speed_swap, duoforge.reference.conformance_pool_data, duoforge.reference.tiebreak_pool_data, duoforge.python.replay); M2 order key instead of the stored Speed (killed by duoforge.moves.speed_swap, duoforge.reference.conformance_pool_data, duoforge.reference.tiebreak_pool_data, duoforge.python.replay); M3 no reset on switch-out (killed by duoforge.moves.speed_swap, duoforge.reference.conformance_pool_data, duoforge.reference.tiebreak_pool_data, duoforge.python.replay); M4 no reset on Mega (killed by duoforge.moves.speed_swap, duoforge.python.replay); M5 reset of both positions when one leaves (killed by duoforge.moves.speed_swap, duoforge.reference.tiebreak_pool_data, duoforge.reference.conformance_pool_data, duoforge.python.replay); M6 bit not set on the target (killed by duoforge.reference.conformance_pool_data, duoforge.moves.speed_swap, duoforge.reference.tiebreak_pool_data, duoforge.python.replay); M7 cause 128 not raised (killed by duoforge.moves.speed_swap); M8 no clear at Stance Change (killed by duoforge.moves.speed_swap); M9 Blade branch without the Speed exception (killed by duoforge.moves.speed_swap, duoforge.reference.tiebreak_pool_data, duoforge.reference.conformance_pool_data, duoforge.python.replay); M10 tracker keeps the bit on a switch (killed by duoforge.python.replay); M11 view bit hidden from the foe viewer (killed by duoforge.moves.speed_swap, duoforge.python.replay); M12 bit cleared at the residual (killed by duoforge.reference.conformance_pool_data, duoforge.moves.speed_swap, duoforge.reference.tiebreak_pool_data, duoforge.python.replay).

Record gate: the engine's record check (`duoforge_public_record_check`) refuses a record with the presence bit (C: `tests/moves/test_speed_swap.c`, check_record_gate, at the basic and Mega points, both players; at the Blade point the cleared state refuses with TEMP_FORME, so only the battle's own refusal is checked there); the live assembler (`python/duoforge_live/record.py`) asks the engine at every swapped point and names the refusal cause 128 from the record's own bit. The move result of Speed Swap is classified by the engine (`MR_SPEED_SWAP` in `src/state/view.c`): true when the exchange line is there; otherwise the hit steps' classes decide: a Protect's block is null, a Psychic Terrain block (turn.c, BLOCKED with detail PSYCHIC_TERRAIN) and a Good as Gold IMMUNE (data/abilities.ts:1630-1641) are false, and a body with no class is refused. So the live tracker assembles the record at those points. The python.replay mismatch of WIP 14a8a577 was a stale build; it passes on the clean build.

Limits and open gaps: the live tracker stops at a FORME_CHANGE line (Stance Change), so the Aegislash end is checked in C only; a swap onto a Substitute (bypasssub) and Mirror Move or Metronome copies of Speed Swap are not recorded. The observation call does not report cause 128; the record path does.
