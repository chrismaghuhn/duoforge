# 5b. G11, Soak

- Area: moves
- Step: G11
- Tests: duoforge.state.pool_tail, duoforge.reference.conformance_pool_data, duoforge.moves.soak

5b. **G11, Soak** (the second mechanic on the tail: the soak type of section 7). Soak keeps its handler id (`DFI_SPECIAL_SOAK`; no table change, so no fingerprint changes) and the turn code implements it; it is marked.
   - **The pin.** `data/moves.ts:17186-17208`: a Water status move, accuracy 100, flags protect, reflectable, mirror, allyanim, metronome; `onHit(target)`: a target whose `getTypes().join()` is `Water`, or for which `setType('Water')` returns false, gives `-fail|target` (the argument is the target, not the user; the move still animates, so no `[still]`) and `null`; otherwise `-start|target|typechange|Water` (no `[from]`). `Pokemon.setType` (`sim/pokemon.ts:2109-2129`, without `enforce`) refuses Arceus and Silvally (species numbers 493 and 773; no pool forme is one, the code still follows the rule) and a Terastallized Pokemon (no Terastallization in the format). The type lasts until the occupant leaves (`clearVolatile` ends with `setSpecies(baseSpecies)`: `sim/pokemon.ts:1508-1560`, called by the switch-out at `sim/battle-actions.ts:117` and by the faint at `sim/battle.ts:2563`) or changes forme: `setSpecies` calls `setType(species.types, true)` (`sim/pokemon.ts:1392`), and `runMegaEvo` goes through `formeChange` (`sim/battle-actions.ts:1902`, `sim/pokemon.ts:1427-1496`), so a Mega Evolution after Soak ends it, with no line; a Soak after the Mega Evolution takes (`g11_soak_mega`).
   - **State and rules.** The tail's `soak_type[roster]` (type id + 1; Water is 18) is the only state. `dfi_types_of` is the one place that reads a member's types: the forme's, or the Soak type alone. STAB (and Adaptability's doubling), the type chart (`dfi_type_immune`, `dfi_type_mod`), grounding (Grassy Terrain's heal and Grass boost, Psychic Terrain's priority block and boost, Grassy Glide's priority), the status immunities (burn on Fire, paralysis on Electric, freeze on Ice, poison on Poison and Steel) and Prankster's Dark rule all call it through the battle. The attacker's own types are unchanged by Soak on a foe: Soak on an ally changes the ally's STAB (`g11_soak_stab`). A move of the user that is stopped by Protect or a miss sets nothing. `dfi_run_mega` clears the soak type; `dfi_tail_clear_occupant` (a switch, a faint, a replacement) already did.
   - **A correction to the state rules (section 7).** The invariant `TAIL_MEMBER` said a soak type is only on a member that is not Mega Evolved, on the assumption that a Mega Evolution always follows Soak. A Mega Evolved Pokemon can be Soaked (`g11_soak_mega`, turn 3), so the rule is only "standing on the field": a weaker rule, no encoded state changes, no new revision. `test_pool_tail.c` had a case that expected the stricter rule (now valid), and the state model (`tools/state_model/state_v3_model.py`) the same.
   - **Event.** New public constant, owner's OK of 2026-10-02: `DUOFORGE_EVENT_TYPE_CHANGE` = 41 (POOL kinds): position, `detail` the new type id (`DUOFORGE_TYPE_*`; Soak: Water 17), `cause` MOVE with `id2` the move; shown to both players (the line is public). The converter reads `-start|X|typechange|TYPE` as one (a line with two types or an unknown type is an error: nothing else in the pool sets a type); with no `[from]` on the line the move is Soak, the one mechanic that sets a single type.
   - **View.** Decision 0018: `TYPE_CHANGED` and `type_now = {Water + 1, 0}` of the position of a Soaked occupant, supported bit 9, set by this step; the tracker's rule is `-start|X|typechange|TYPE` sets it, and a `|switch|`, `|drag|`, `|replace|`, `|faint|` or `|-mega|` of the position clears it (the research table of section 6.1 had OUT only; the Mega Evolution is added).
   - **Evidence.** Four recorded battles under the POOL kind (`g11_soak`, `g11_soak_mega`, `g11_soak_stab`, `g11_soak_electro`; `duoforge.reference.conformance_pool_data` compares every event, HP and request with the reference, which is where the `-supereffective`, `-resisted` and `-immune` lines, the STAB through the HP that is left and the Grassy Terrain heal of the grounded Pelipper are read); `duoforge.moves.soak` reads the tail's soak type of every member and both viewers' whole extension after every step against rows that `tools/reference/test_trace_to_c.py` derives from the protocol lines; the interaction table of the pin is in that test's header. Mutation checks (the engine's read of the soak type, the clear on Mega Evolution, the clear on a switch, the pure-Water test, the view bit, the converter's line) each fail a test.
