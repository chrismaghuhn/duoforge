5dx. **Skill Swap fails on every pool ability with failskillswap (issue #620; branch chris/skillswap-failskillswap-fix; found by the code review of #618).** The pin's `skillSwap` returns false when either holder's ability has the `failskillswap` flag (`sim/battle.ts:1316`), and the move prints `-fail|USER` with `[still]` on its move line (decision 0041). `dfi_fails_skillswap` (`src/combat/turn.c`) read only Stance Change, so a Skill Swap at an Illusion holder (`data/abilities.ts:2091`, marked by I2) swapped the two abilities where Showdown fails the move. Decision 0041's sentence "none on main" had been stale since G66 marked Stance Change and I2 marked Illusion; it is corrected there. Now `dfi_fails_skillswap` reads the holder's current ability against the pool's five abilities with the flag: Disguise, Hunger Switch, Illusion, Stance Change and Zero to Hero (only Illusion and Stance Change are marked; the other three cannot reach a battle). The disguise does not matter: the pin reads the holder's own ability, and the `-fail` line is public in both streams, so the decision 0041 refusal planned for a possible Illusion is not needed. The pool has no ability-flag column, so the list is written in the turn code and `tools/datagen/gen_closure.py` checks it: `FAILSKILLSWAP_ABILITIES` and `check_failskillswap`, run by `build_pool` over all pool ability rows (215), read each row's flags from the pin (the Champions entry's own `flags` where it has one, else the inherited base entry's; every Champions ability entry inherits) and fail on any other set. The same check reads the `DFI_ABILITY_*` names of the body of `dfi_fails_skillswap` from `src/combat/abilities/skill_swap.h` (`FAILSKILLSWAP_SOURCE`; the path moves with the function) and fails when they are not the list, so the C list and the Python list cannot drift apart. A changed list on either side fails `duoforge.data.pool_regen`. Of the pin's 29 abilities with the flag, the other 24 are not pool rows: both As One, Battle Bond, Comatose, Commander, the four Embody Aspect, Ice Face, Multitype, Neutralizing Gas, Poison Puppeteer, Power Construct, Protosynthesis, Quark Drive, RKS System, Schooling, Shields Down, Tera Shell, Tera Shift, Teraform Zero, Wonder Guard and Zen Mode (Gulp Missile and Imposter do not have the flag). The pool tables are unchanged (canonical sha256 `d6eee672`, so no fingerprint moves). No new public value. The ability code stays in `turn.c` (the restructure lane moves it later). **Evidence.** `g70_skillswap_illusion` (a POOL battle, recorded with the pinned Showdown b2cb775, `ps_trace.js --check` matches; all content marked, learnsets from `data/mods/champions/learnsets.ts`): Zoroark leads disguised as Gholdengo; turn 1 Gardevoir's Skill Swap at the disguised holder prints `|move|p2a: Gardevoir|Skill Swap||[still]` and `|-fail|p2a: Gardevoir`; turn 2 Espeon's Dazzling Gleam breaks the disguise (Focus Sash) and the Skill Swap at the shown Zoroark fails the same way. On main (55bc3f34) `diff_driver.py corpus` on a scratch corpus holding only this battle answers DIVERGENCE at step 1 (event 7 of both players); with the fix PASS. It is committed as a pool battle (pins by `capture_battle_pins.py` for this battle only; payload regenerated; the pool set grows by one, the bound in `tests/reference/pins/reg-mc.json` unchanged). White-box `check_decisions` in `tests/moves/test_skill_swap.c` (`duoforge.moves.skill_swap`): each of the five abilities on the user and on the target gives `DFI_SKILL_SWAP_FAILS`, two flagless abilities proceed. Generator tests `FailSkillSwap` (`tools/datagen/tests/test_gen_closure.py`, nine cases: the list equals the pin set; Disguise's multi-line flags with a trailing comma; another pool ability with the flag; a listed ability without it; a Champions entry with its own flags; the C body names the list; a C body with an id missing, with another or a repeated id, or without the function is refused).
