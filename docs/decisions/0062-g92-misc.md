## The result of a confusion move (pin lines, 2026-10-11)

Every printed line of the confusion moves is from the pin (Showdown b2cb775). The engine implements these three rules:

1. **`[still]` and `-fail` of an ineffective Confuse Ray, Teeter Dance (or a Swagger or Flatter whose boost and confusion both fail).**
   - The volatile: `addVolatile` returns `false` for a target that is confused already (`sim/pokemon.ts:1983-1986`), and returns the `TryAddVolatile` result otherwise (`:1994-1998`).
   - The boost of Swagger and Flatter returns a boolean; `runMoveEffects` combines it with the volatile's result by `combineResults` (`sim/battle-actions.ts:1561-1573`): a `false` beats a `null`, and a `true` beats a `false`.
   - `runMoveEffects` ends with `if (!didAnything && didAnything !== 0 && ...)` and, for `didAnything === false`, `add('-fail', source)` and `attrLastMove('[still]')` (`sim/battle-actions.ts:1303-1307`). So the user shows the `-fail` and the move line carries `[still]`. The engine: `dfi_confuse_primary` reports the target as not changed, and `dfi_fail_still` runs when no target changed and one target was false.
2. **The empty spread list of a Teeter Dance without an affected target.**
   - `trySpreadMoveHit` filters the targets by the results of the hit steps: `targets = targets.filter((val, i) => hitResults[i] || hitResults[i] === 0)` (`sim/battle-actions.ts:605`). A target whose `runMoveEffects` result is `false` or `null` drops out.
   - The spread attribute is `attrLastMove('[spread] ' + hitSlot.join(','))` (`sim/battle-actions.ts:618`) over the targets that remain, so no target gives `[spread] ` with nothing after it. The engine: the spread mask of a confusion move holds the targets whose change happened.
3. **Misty Terrain's refusal prints no `[still]`.**
   - Misty's `onTryAddVolatile` prints `-activate` and returns `null` for a grounded target that is not semi-invulnerable (`data/moves.ts:12177-12186`). `addVolatile` passes that `null` back (`sim/pokemon.ts:1994-1998`), so the target's result is `null`, not `false`.
   - `runMoveEffects` prints the `-fail` only for `didAnything === false`, so a `null` does not print it (`sim/battle-actions.ts:1303`). A refused boost with the Misty `null` is still `false` (`combineResults`), so that case fails as in rule 1.

Mixed cases (a Teeter Dance that reaches some targets but not others): by the same combination a single `true` wins, so the move does not fail, and the spread list names only the targets reached. The campaign counts these cases (Teeter Dance with 0, 1, 2 and 3 confused targets).
