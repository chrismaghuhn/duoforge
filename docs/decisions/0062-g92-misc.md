## The result of a confusion move (pin lines, 2026-10-11)

Every printed line of the confusion moves is from the pin (Showdown b2cb775). The engine implements these three rules:

1. **`[still]` and `-fail` of an ineffective Confuse Ray, Teeter Dance (or a Swagger or Flatter whose boost and confusion both fail).**
   - The volatile: `addVolatile` returns `false` for a target that is confused already (`sim/pokemon.ts:1983-1986`), and returns the `TryAddVolatile` result otherwise (`:1994-1998`).
   - The boost of Swagger and Flatter returns a boolean; `runMoveEffects` combines it with the volatile's result by `combineResults` (`sim/battle-actions.ts:1561-1573`): a `false` beats a `null`, and a `true` beats a `false`.
   - `runMoveEffects` ends with `if (!didAnything && didAnything !== 0 && ...)` and, for `didAnything === false`, `add('-fail', source)` and `attrLastMove('[still]')` (`sim/battle-actions.ts:1303-1307`). So the user shows the `-fail` and the move line carries `[still]`. The engine: `dfi_confuse_primary` reports the target as not changed, and `dfi_fail_still` runs when no target changed and one target was false.
2. **The empty spread list of a Teeter Dance without an affected target.**
   - `trySpreadMoveHit` filters the targets by the results of the hit steps: `targets = targets.filter((val, i) => hitResults[i] || hitResults[i] === 0)` (`sim/battle-actions.ts:605`). A target whose `runMoveEffects` result is `false` or `null` drops out.
   - The spread attribute is `attrLastMove('[spread] ' + hitSlot.join(','))` (`sim/battle-actions.ts:618`) over the targets that remain, so no target gives `[spread] ` with nothing after it. The engine: the spread mask of a confusion move holds the targets whose change happened.
3. **Misty Terrain's refusal prints no `[still]`.**
   - Misty's `onTryAddVolatile` prints `-activate` and returns `null` for a grounded target that is not semi-invulnerable (`data/moves.ts:12177-12186`). `addVolatile` passes that `null` back (`sim/pokemon.ts:1994-1998`), so the target's result is `null`, not `false`.
   - `runMoveEffects` prints the `-fail` only for `didAnything === false`, so a `null` does not print it (`sim/battle-actions.ts:1303`). A refused boost with the Misty `null` is still `false` (`combineResults`), so that case fails as in rule 1.

Mixed cases (a Teeter Dance that reaches some targets but not others): by the same combination a single `true` wins, so the move does not fail, and the spread list names only the targets reached. The campaign counts these cases (Teeter Dance with 0, 1, 2 and 3 confused targets).

## Addendum (2026-10-11): the boost cap, Memento into a Substitute, the mutants, the -ohko line

**The result of a Swagger or Flatter at the cap (corrects rule 1).** `boost()` starts with `let success = null` (sim/battle.ts:2035) and sets `success = true` only when a stat changed (:2042-2050). A boost already at the cap prints `-boost|X|atk|0` for a move effect that is neither secondary nor self (the else branch, :2079-2080) and stays null; `return success` (:2088) is null, not false. The volatile's answer is false when the target is confused already (sim/pokemon.ts:1983-1986) and null when Misty Terrain's onTryAddVolatile refuses it (data/moves.ts:12177-12186). The two combine by combineResults (battle-actions.ts:1561-1573: true beats any, false beats null, null beats undefined):
- +6 with Misty: null + null = null: no -fail, no [still] (the reference of fz_9301_28, step index 21).
- +6 with the target already confused: null + false = false: -fail and [still].
- fresh confusion, with or without the cap: true: the move succeeds.
The engine: a target fails only when an existing confusion refused the volatile (not the terrain) and no boost changed a stat. A boost at the cap is not a failure. Recorded: g92_misty_clamp_boost (from campaign battle fz_9301_28).

**Memento into a Substitute does not faint the user (corrects my earlier faint).** The Substitute's onTryPrimaryHit returns null after `-fail|source` (data/moves.ts:18341-18350). spreadMoveHit keeps the target at null, which is not HIT_SUBSTITUTE, so `if (!damage[i]) targets[i] = false` (battle-actions.ts:1067-1070) makes it false, and runMoveEffects skips false targets before its selfdestruct check (`if (target === false) continue`, then the check at :1287). The reference is g92_memento_sub: `|move|...|Memento||[still]` and `-fail|Gardevoir`, no faint. The engine's faint in that path was removed. M7 now adds that faint, and it is caught.

**Spread lists (the rule the minimal case fz_9201_0 passes, mask 14).** Once one target is affected, every target that reached the hit loop stays in the [spread] list, including unaffected ones (sim/battle-actions.ts:955 breaks only when every damage is false; :963 turns a false, null or undefined into 0; the filter at :605 keeps 0). Only when no target is affected is the list empty (:974, `damage.fill(false)`). A single replay of fz_9201_0 passes. The all-Misty case (only null results) gives an empty list and no -fail, recorded in g92_teeter_misty_all.

**M4 (accuracy 20 for every non-Ice user) is not equivalent.** The pin gives an OHKO move (ohko true) accuracy 30 plus the level difference (battle-actions.ts:696-706), and every Pokemon is level 50, so 30 with no Ice rule. The mutant's 20 changes every Fissure, Guillotine and Horn Drill roll in [20, 30). The cover is g92_m4_cover (campaign battle fz_9301_107, step index 17: Excadrill's Fissure on Feraligatr, the step's only accuracy roll, 22, hit: `0 fnt`, `-ohko`). The first M4 run never judged the mutant: the mutation left the `sheer_cold` parameter unused, the build failed under -Werror, and the script reported a survivor. The mutant now keeps the parameter in use.

**M6 (the Memento faint moved before its target's boosts) is equivalent.** `dfi_queue_self_faint` queues the faint and emits no event at that point; the boosts' events come from the same loop, so moving the call changes no emitted line. The reference (g92_memento, g92_memento_sub) prints the unboosts and then the faint, which the engine's emission order matches. Not a test gap.

**M11 (a capped boost under Misty counts as a failure) is reachable and is caught by g92_misty_clamp_boost.** The mutant restores the earlier rule, which treated a boost-present case as a failure whatever the boost returned.

**The bare `-ohko` (ORACLE_GAP, fz_9301_94 and fz_9301_308).** The pin prints `-ohko` after the faint messages (sim/battle-actions.ts:976, then :1000), and a KO that ends the battle prints `|win|` in that same phase. The converter now accepts the bare line after a faint or after `|win|`, when the step's last move is an OHKO move. Both cases convert, and the converter's unit tests pass.
