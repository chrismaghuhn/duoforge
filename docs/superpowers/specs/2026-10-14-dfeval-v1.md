# DFEVAL version 1: cold evaluator artifact and workspace contract

E2 implements the loading/memory boundary approved in
[in-engine evaluation](2026-10-14-in-engine-evaluation-design.md), sections 3 and 5–9.
It implements no network inference, private conversion, distillation or adoption.
E3g now registers the full/small/medium declarations approved in #569, with the
exact [compiled graph contract](2026-10-15-e3g-graph-contract.md). Unknown graphs
return `E_UNSUPPORTED`, `eval_graph_unregistered`. E2's toy fixture descriptor
remains private whitebox-only and is never registered by the public loader.

## Opened-file identity and lifecycle

`duoforge_eval.h` adds four cold lifecycle operations. Loading requires an absolute
caller-selected private path, a mandatory external expected SHA-256, context,
encoder version and feature mask. There is no discovery, download, embedded trained
model, reload, pickle, arbitrary graph execution or implicit JAX switch. Diagnostics
contain a phase/reason and `leaf=UINT32_MAX`, never a filesystem path or metadata.
Output handles remain untouched on every refusal.

The actual opened stream is measured and hashed in bounded 4 KiB chunks. A global
1 GiB hard limit applies before allocation; a registered descriptor additionally
sets its reviewed file limit. The private successful path rewinds the same open
file, reads an exact bounded snapshot, verifies EOF and hashes **that snapshot**
again against the expected full-file hash before parsing/publishing. This catches
changes between the two reads; the first pass alone is insufficient. No pathname
is reopened. The immutable snapshot owns the tensor bytes. Public unavailable
loads hash with bounded scratch and never allocate a weight slab.

Encoder 6 is the only current input version. Context fingerprint, semantics ID,
context schema, exact encoder mask, widths, feature/group digest, input-layout
mapping digest, arithmetic version and registered graph identity must match.
The current encoder-6 mask has bits 0–46. The file cannot declare its own approval.
The adoption tuple remains private `(artifact hash, code/schema, context)`; a
successful load is not an adoption gate.

A workspace retains model storage, so releasing the caller's model handle does not
invalidate it. Its identity binds the actual model handle (therefore hash/schema),
copied context, exact worker count and leaf capacity. It reserves exactly
`workers * descriptor.scratch_per_worker + capacity * descriptor.scratch_per_leaf`
bytes after division-before-product, addition and descriptor maximum checks. Zero
capacities/workers are invalid; excessive capacity/workers/scratch is `E_CAPACITY`,
`eval_workspace_capacity`. No thread pool is created here: integration will use the
existing batch workers. Descriptor scratch regions must respect their scalar
alignment, and E3g adds the concrete tensor/tile layout and resource report.

Private acquire/release operations perform no allocation, free, resize or file I/O.
One active caller owns a workspace; a second caller and destruction while active
refuse `E_UNSUPPORTED`, `eval_workspace_busy`. Calls bound to another model/context
or worker count refuse before ownership/scratch changes. Destruction must not race
use/destruction of the same handle. Internal bounded mutexes protect ownership and
cold reference counts; no shared mutable error buffer exists.

E2 proves warmed available workspace operations only. The full allocation-free
expand/project/digest/inference dispatch gate remains pending E3/E5 integration.
No inference throughput or learned fidelity is claimed.

## Canonical bytes

All integers are unsigned little-endian wire fields. Tensor payloads use signed
two's-complement integers in the declared width. These tags are private artifact
schema tags, not public gameplay identifiers. Struct padding/host endianness is
never serialized. No extension records, unknown keys or trailing bytes are allowed.

### Fixed header: 256 bytes

| Offset | Bytes | Field |
|---:|---:|---|
| 0 | 8 | `DFEVAL\0\0` |
| 8 | 4 | format version, exactly 1 |
| 12 | 4 | header bytes, exactly 256 |
| 16 | 8 | complete file length |
| 24 | 4 | compiled graph identity |
| 28 | 4 | compiled arithmetic version |
| 32 | 4 | encoder version, currently 6 |
| 36 | 4 | observation width, currently 1,094 |
| 40 | 8 | exact encoder extension mask |
| 48 | 4 | `DUOFORGE_SEMANTICS_ID` |
| 52 | 4 | `DUOFORGE_CONTEXT_SCHEMA_VERSION` |
| 56 | 4 | exact descriptor tensor count; hard limit 128 |
| 60 | 4 | metadata bytes; hard limit 65,536 |
| 64 | 8 | directory offset, exactly 256 |
| 72 | 8 | metadata offset, exactly `256 + count * 128` |
| 80 | 8 | data offset, exactly 8-byte-aligned metadata end |
| 88 | 4 | exact context species table count |
| 92 | 4 | exact context move table count |
| 96 | 32 | engine context fingerprint |
| 128 | 32 | full teacher checkpoint SHA-256; nonzero |
| 160 | 32 | full calibration/quantization manifest SHA-256; nonzero |
| 192 | 32 | descriptor feature-name/group SHA-256 |
| 224 | 32 | descriptor input-layout/classification SHA-256 |

Table counts are context counts, not teacher embedding capacities. Embedding id
capacities and all dimensions are explicitly fixed by the descriptor's tensor
shapes. The input-layout identity fixes categorical recovery/classification; E3a
implements those inputs, and E3g must register descriptors only after review of
**all** input columns/capacities. No filename/model nickname substitutes for a hash.

### Exact directory: 128 bytes per tensor

Entries occur in **compiled descriptor order**, with an exact inventory. A missing,
duplicate, reordered, renamed or additional tensor fails; it cannot decrease graph
coverage. A tensor failure names its compiled tensor as `eval_tensor_invalid:<name>`.

| Relative offset | Bytes | Field |
|---:|---:|---|
| 0 | 32 | ASCII descriptor name, NUL terminated, remaining bytes zero |
| 32 | 4 | dtype tag: 1=I8, 2=I16, 3=I32, 4=I64 |
| 36 | 4 | rank, 1–4 |
| 40 | 16 | four dimensions; unused dimensions zero |
| 56 | 8 | data offset |
| 64 | 8 | exact element product times dtype width |
| 72 | 8 | scale offset, zero only if scale count is zero |
| 80 | 4 | exact compiled scale count |
| 84 | 44 | reserved, all zero |

Data begins at the header's data offset. For each directory entry: its exact
payload, zero padding to the next multiple of eight, then its scale records.
The next tensor starts immediately there. Scale records are eight bytes each:
positive `uint32 multiplier`, `uint32 shift` in 0–63. Their count is fixed in the
descriptor (per-output-channel for dense weights). After the last entry the cursor
must equal the full file length. Thus overlaps, gaps, nonzero padding, offsets
inside the header/directory/metadata, truncated extents and trailing bytes refuse.
Length products are checked before multiplying or accessing.

The descriptor, never the file, fixes fan-in, activation absolute bound, bias
absolute bound and every scratch/file maximum. For I8 dense weights, loading scans
the actual maximum absolute weight and proves
`bias_abs + fan_in * activation_abs * weight_abs <= INT64_MAX`, then proves that
bound times every positive channel multiplier also fits `INT64_MAX`. This
conservative common bound proves every channel; no signed overflow is evaluated.
I64 biases are inspected as unsigned magnitudes, including explicit refusal of
`INT64_MIN` or a magnitude above the descriptor bound. Input bound is at most
2^31 where E3g's compiled I32 torso/head requires it; earlier I16 nodes retain
32,768. The shift/scale representation matches E3a. E3g adds the explicit
normalization/embedding/pooling graph-specific proofs in its contract; merely
matching a shape is insufficient.

### Canonical UTF-8 metadata subset

The exact grammar is ASCII, a valid subset of UTF-8. Non-ASCII, CRLF, arbitrary
keys, duplicate keys, extra lines, spaces and alternate numeric spellings refuse.
Six lines occur in this exact lexical order, with a final LF:

```text
export_commit=<40 lowercase hex bytes>
export_dirty=<0 or 1>
seed=<canonical uint64 decimal, no leading zeros except 0>
split_sha256=<64 lowercase hex bytes>
training_commit=<40 lowercase hex bytes>
training_dirty=<0 or 1>
```

The split digest identifies the private split manifest, which records all groups,
seeds and datasets. The calibration manifest similarly describes scale provenance.
Teacher and manifest SHA-256 values are full binary digests in the header; no
truncated checksums are accepted. Private manifests and payloads stay outside the
repository and CI artifacts. Public CI creates only deterministic toy parameters
in temporary storage, then deletes them.

## E2 verification boundary

The independent Python oracle constructs bytes with `struct`/`hashlib`, without
importing loader implementation or a real exporter. Its C harness verifies exact
expected refusals, atomic handles, valid SHA/context snapshots, malformed version,
context, feature mask, schema, inventories, offsets, metadata, scales, tensor/bias
bounds, first-pass/second-snapshot mutation and every cold allocation site.
Workspace tests cover maximum and one-past capacity, worker/model/context binding,
checked scratch products, real concurrent ownership refusal, retained model
lifetime, unchanged sentinel scratch, and zero allocator/free calls in 1,000 warmed
acquire/release cycles. The artifact is removed before the workspace tests, proving
that these operations do not reread it. ASan/UBSan and platform builds check memory
boundaries; compiler/IPO provenance and the exact export list are recorded in the
implementation PR report. These are infrastructure gates, not E4 fidelity or E5
integrated memory/latency gates.
