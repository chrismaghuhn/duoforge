# Learner v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the learner train on many real teams: library-checked teams, N² weighted pairings, a league, an entropy schedule, resumable runs, a ladder per team and model v2. Measure it on Teams A, B and C.

**Architecture:**
- The synchronous loop of decision 0014 is extended (approach A).
- The C batch gets one additive call: reset environments with new setups.
- The engine package `python/duoforge` stays NumPy-only. It gains feature names and the team pool.
- Everything that learns lives in `python/duoforge_learn` (JAX, optax), behind one `policy.Model` interface for v1 and v2.

**Tech Stack:** C11 (the library and its CTest tests), Python 3.12 with NumPy 2 (engine package, unittest), JAX 0.11 and optax in WSL `~/df-learn` (learner tests and runs).

**Spec:** `docs/superpowers/specs/2026-10-02-learner-v2-design.md`. The section numbers below (S5.1 and so on) refer to it.

## Global Constraints

**Errors**
- No silent fallback. Every refusal is an exception or a status that names its cause (team, member, table, name, column, env, status). Nothing is clipped, skipped or defaulted (S16).

**Packages and determinism**
- `python/duoforge` imports only NumPy and the standard library. JAX and optax only in `python/duoforge_learn`.
- Battle seeds stay `duoforge_batch_seeds(batch seed, env, episode)`.
- Pairings, league slot choices, snapshot draws and the eval suite are pure functions of (run seed, tag, env or update, episode). The formula is in Task 8.
- No (env, episode) pair may repeat within a run, also across resumes.

**Library**
- No new allocation on a per-step path. `duoforge_batch_reset_setups` allocates exactly as `duoforge_batch_reset` (one battle per reset).
- Versions are assigned by the HauptSession at merge. Before opening a C PR, ask it for the number.
- A bump edits `include/duoforge/duoforge.h` (MINOR and STRING), `python/duoforge/_lib.py` `EXPECTED_VERSION`, `python/tests/test_lib.py` (two lines) and `tests/test_api_atomicity.c`.

**Model and run defaults**

| Setting | Default |
|---|---|
| Model v2 capacities | species 1024, move 1024, item 256, ability 256, nature 25 |
| Preset S | embed 32, member 64, position 64, hidden 256 × 2 layers, option 64 |
| Preset M | 64 / 128 / 128 / 640 × 3 / 128 |
| Preset L | 64 / 256 / 256 / 1024 × 5 / 256 |
| `--self-play-share` | 0.5 |
| `--league-slots` | 4 |
| `--snapshot-every` | 200 |
| `--slot-refresh` | 50 |
| `--save-minutes` | 10 |
| `--eval-games` | 2 |
| `--eval-budget` | 512 |
| Bootstrap resamples | 200 |

**Checkpoints**
- Every new checkpoint writes `"encoder": 2`.
- Every loader sets `legacy_present = config.get("encoder", 1) < 2` and passes it to `features.encode_batch(..., legacy_present=...)`. The encoder-fix PR (HauptSession) provides the switch.

**Tests and process**
- Tests are `unittest`. NumPy-only modules are registered in the `foreach` list of `tests/CMakeLists.txt` (run with `DUOFORGE_PYTHON`). JAX modules go in the `DUOFORGE_LEARN_PYTHON` block (run in WSL `~/df-learn`).
- Every PR passes `tools/ci/local_ci.sh` with all 11 jobs before it is handed over. The script takes the machine lock.
- Every code PR gets a review agent (`fullstack-dev-kit:pr-reviewer`, model opus). Verify each finding before you change anything.
- The HauptSession merges with merge commits. Send it the PR number, the head and the CI result.
- Stage files by name. Never `git add -A`: worktrees of other agents sit inside the repo.
- Training runs and measurements are announced to the HauptSession beforehand. Measurements run only on a quiet machine.

## Review Focus

1. **Env count changes across resumes.** A resume with fewer environments, then one with more again, must not reuse an (env, episode) pair. Episode numbers are kept for every env index ever used (Task 13 test `test_shrinking_then_growing_envs_never_repeats_an_episode`).
2. **Line endings.** A team file checked out with CRLF line endings on Windows and LF on Linux must parse identically and hash identically. Otherwise a resume on another OS is refused for a "changed" team (Task 17 test `test_crlf_and_trailing_spaces_parse_and_hash_like_lf`).
3. **Cut-off episodes.** An episode that ends by the `--max-steps` cut-off must release its league slot like a terminal one. Otherwise a draining slot never reloads (Task 10 test `test_cut_off_episodes_release_their_slot`).
4. **Mixed encoder revisions.** A ladder game between a pre-fix checkpoint and a new one encodes each seat with its own player's `legacy_present` (Task 15 test `test_each_seat_uses_its_players_encoder_setting`).
5. **Degenerate team weights.** A zero, negative or non-finite weight, or all weights zero, is refused when the pool is built. A zero weight is allowed and that team is never drawn (Task 8 test `test_weights_are_validated_and_zero_weight_is_never_drawn`).
