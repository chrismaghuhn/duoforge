# P1 expert-data contract (C1)

`expert_data.py` contains data validation, versioned selection keys and pre-action admission only. It does not collect games, search, train or change existing play paths. See the [approved P1 plan](../../docs/superpowers/plans/2026-10-08-stage3-p1-pilot.md); worker/ledger amendment [#246](https://github.com/chrismaghuhn/duoforge/pull/246).

`DataManifest` pins source/checkpoint/model/id/pool/belief hashes, encoder and dimensions, seeds/key version, CPU runtime/compiler, capacity 1024, worker count (4/8/14), 512 parallel games, complete-round game count, `first_game_id` (rows must use logical game ids `first_game_id..first_game_id+game_count-1`; production ids are disjoint from the smoke round), split seed and budget/evaluation metadata. `teacher_config` is exactly {k, m, worlds, lam}: any later key or value (C3: rule, seed, work caps, audit rate) must bump `SCHEMA_VERSION`, so older shards and cursors are refused explicitly instead of read with defaults. The selected count must be frozen in the manifest; changing it invalidates shard/cursor resume. Worker selection and the compute ledger are external contracts, not implemented here.

`ExpertRow` stores **only learner public-view rows**. `logical_tick` is mandatory on every row, including waiting rows: a step index within its game, distinct from request epoch and `LabelCursor.logical_tick` (the controller admission tick). Row identity is `(game_id, seat, logical_tick)`. Shards reject duplicate/regressing ticks per game/seat; acting rows also need strictly increasing `request_epoch` per game/seat, while waiting rows may share a decision key. A row read from a shard must carry every field (no defaults for `logical_tick`, `work` or `audit`). TERMINAL rows are not stored: `returns.gae` has no terminal step, so `done` on the last stored row ends the episode. The learner trajectory assembler must check gaps/completeness across shards before GAE. Boundary and masks are explicit: pair masks 32×32, preview masks 360 from native legality; only TURN/REPLACEMENT/PIVOT roots with >=2 legal actions can be TARGET, CAP_RAW, PUBLIC_REFUSAL or WORK_EXHAUSTED (so the >1% fallback counter sees eligible roots only); a requested row is FORCED exactly when it has one legal action; preview rows play raw as UNSELECTED. No legality or battle rules are inferred in Python.

Stored reward/done/collector-value/bootstrap preserve the existing GAE inputs; this module does not compute returns. Target rows carry a sparse distribution over up to eight full joint ids, include the raw sampled action, and record the actual tau(action) log-probability. Other requested rows execute their pre-drawn raw action; explicit refusal/exhaustion rows name a cause and have no label. Forced/waiting rows have their own status. Runtime arrays/configs are detached and read-only, including signed-zero float bits.

`selection_word(key, seed, domain=..., version=1)` uses SHA-256 with the specified version tag, length-prefixed domain, and little-endian uint64 key fields. Supported domains are raw/SELECT/world/X/audit/split. `is_selected(key, seed)` is the random 1/8 gate in code: SELECT word < `SELECT_THRESHOLD` = 2**61, with the manifest `seed`; this is not every eighth arrival. `is_held_out(game_id, split_seed)` is the whole-game held-out split for Learner v2: split word of `DecisionKey(game_id, 0, 0)` with the manifest `split_seed` < `HELD_OUT_THRESHOLD` = floor(2**64/5) (20%). It is fixed before collection, every row of a game shares it, and rows are never reassigned; held-out rows stay in the label cap. Unknown domains/versions or invalid keys fail explicitly. No worker/order/time dependency.

For admission, the controller first assembles the **complete logical tick** of eligible selected roots as `AdmissionRequest(key, boundary, legal_count)`; anything but TURN/REPLACEMENT/PIVOT with >=2 legal actions is refused. `admit_tick` sorts requests by logical game id, reserves tickets in-place and permanently marks overflow games cap-raw **before** teacher execution. The adapter must obey that disposition; admission itself executes nothing. A pending tick blocks further admission. `commit_tick` requires all outcomes together and returns a new cursor: successful targets consume tickets; named public/work refusals release tickets at commit. No post-action target dropping. Cursor snapshots preserve pending reservations, dropped games, per-game epochs and logical tick, with exact manifest/integrity checks. Permuted teacher execution cannot change the complete-tick admission ordering.

`write_shard` writes canonical JSON with dtype/shape/base64 array bytes, content/manifest SHA-256 and fsync; returns file SHA-256. It refuses an existing path rather than overwrite private data. A failed partial write is invalid and explicitly refused on read; the caller must retain it for diagnosis and choose a new shard. `read_shard` validates integrity/schema/manifest/rows. `write_manifest`/`read_manifest` store the run manifest in the same canonical form as each shard header (same `manifest_sha256`; every field required, integrity and `validate_manifest` checked), so consumers load it with `read_manifest` and pass it to `read_shard` instead of building a `DataManifest` themselves. A shard holds at most `MAX_SHARD_ROWS` = 4096 rows: a row is about 10.7 KB of JSON+base64 (measured on the synthetic encoder-4 row), so a shard stays near 44 MB for one `json.loads`, and 15-20k games need roughly 3-6 GB of private disk. The smoke forecast must budget that disk and read time with the generation cap. Both refuse repository paths through `duoforge_replay.dataset.refuse_repository`; no real shards, cursor files, tables or checkpoints belong in Git or CI artifacts. The live collector/learner will own shard boundaries and trajectory completion in their later PRs.

Tests use synthetic data and temporary directories. Local verification is limited to the three plan selectors on `python/tests/test_expert_data.py`; hosted CTest registers `duoforge.python.expert_data` for the full CI matrix. Learner v2 full-joint API and loop remain separate (#245/#244).
